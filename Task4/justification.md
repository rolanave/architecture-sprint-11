# Обоснование конфигурации

Конфигурация включает собой упрощенную модель решения, которая включает в себя несколько компонент, таких как:
- Портал, доступный извне клауда для пользователей (белый IP и правила безопасности для доступа извне) 
- Комопнента каталога данных
- Компонента, моделирующая оркестратор данных
- Копмопнента, моделирующая APIGW для функциональных приложений источников данных (финансовая)

Для упрощения конфигурации :
- в пример не было включен сервер аутентификации и авторизации (Keycloak)
- в пример не было включен балансировщик и все комопоненты запускались в режиме одного инстанса
- каждый компонент представлял собой пустой Ubuntu сервер 
- была создана только одна подсеть
- интеграция с внешним DWH 


Каждый сервер запускался с минимальными ресурсами (2 CPU, 2Gb, 10Gb для запуска Ubuntu), кроме сервера, который эмулировал Nifi, так как в системной требованиях для компонента указано 2 CPU и 4 Gb


# Обоснование использования IaC подхода

IaC подход (использование terraform и описание желаемой конфигурации языке HCL) позволяет:
- упросить разворачивание и воспроизводимость деплоймента с нуля, за счет описания желаемой конфигурации
- ускорить внесение изменений, так как утилита анализирует разницу между развернутым окружением и желаемым и вносит дополнения не затрагивая работу тех частей конфигурации, которая не менялась
- упростить описание и масштабирование компонент, за счет возможности переиспользования описания запуска компонент по шаблону и используя массивы инициализаторов из переменных (не вошло в пример конфигурации)
- реализовать дополнительные валидации и тесты конфигурации, которые позволяют найти ошибки/конфликты конфигурации до обновления ее на живом окружении (не вошло в пример конфигурации)
